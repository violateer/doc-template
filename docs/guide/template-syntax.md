# 模板标记写法

模板文件就是普通的 `.docx` / `.xlsx`，标记直接写在文档里，生成时由内置渲染器替换。两种模板共用一套标记语法，区别只在「能写在哪里」。

## 通用占位符

| 写法 | 含义 | 示例 |
| --- | --- | --- |
| `${key}` | 取参数 `key` 的值 | `${report_no}` → `QC2026001` |
| `{{key}}` | 同上，两种写法完全等价 | `{{report_no}}` |
| `${key:默认值}` | 取不到值时用默认值 | `${inspector:未填写}` |
| `${key\|type:参数}` | 值转换（时间格式化、千分位、字典…） | `${amount\|number:2}` → `12,345.00` |
| `${a.b.c}` | 按点号逐级取嵌套值 | `${customer.name}` |
| `${块编码.字段}` | 取数据块结果（块编码做命名空间） | `${report.product_name}` |

- 花括号内的空格会被忽略，`${ report_no }` 与 `${report_no}` 等价。
- 键名**大小写不敏感**：模板写 `${Report_No}` 也能匹配参数里的 `report_no`。
- 默认值只在「键不存在」或「值为 `null`」时生效；值本身是空串时按空串输出。
- 值的渲染规则：`null` → 默认值或空串；数字去掉多余的 0（`1.50` → `1.5`、`2.0` → `2`）；对象 / 数组输出成 JSON 字符串。
- 转换链写在默认值之后、用 `|` 分隔，可串联：`${amount:0|number:2|upper}`。详见 [字段值转换与字典](./converters.md)。

## 明细行循环

数组通常来自 `single: false` 的数据块，用 `{{#each 数组}}` 标记重复（也接受 `${#each 数组}`，推荐前者）：

| 位置 | 写法 | 行为 |
| --- | --- | --- |
| DOCX 表格行 | 该行任意单元格写 `{{#each items}}` | 整行按数组重复，**单标记隐式闭合**，不需要 `{{/each}}` |
| DOCX 表格区域 | `{{#each items}}` / `{{/each}}` 各独占一行 | 两行之间的**所有行**整体重复 |
| DOCX 段落块 | `{{#each items}}` / `{{/each}}` 各独占一段 | 两段之间的段落整体重复 |
| XLSX 行 | 该行任意单元格写 `{{#each items}}` | 整行复制（值 + 样式 + 行高），向下插入 |
| XLSX 区域 | `{{#each items}}` / `{{/each}}` 各独占一行 | 之间的行整体重复 |

数组表达式支持点号路径，例如 `{{#each report.items}}`。

循环体内取当前项：

- `${product_name}` 直接取当前项的字段，**当前项优先于外层参数**；
- `${item.product_name}` 等价写法，字段名与外层参数重名时用它更安全；
- 数组为空（或值为 `null`）时：表格行 / Excel 行整行删除，区域与段落块整块清空；
- 数组变量**根本不存在**时直接判定生成失败，错误信息会列出当前可用的参数 —— 避免「行莫名其妙没了」却查不出原因。

### 递归渲染：循环行下面再挂一个列表

区域循环可以**嵌套**，层级不限。典型场景是主表行 + 它自己的明细列表：

```
{{#each orders}}            ← 外层区域开始（独占一行）
${order_no} | ${customer}
{{#each items}}             ← 内层区域开始（独占一行）
  ↳ ${sku} | ${qty}
{{/each}}                   ← 内层区域结束
{{/each}}                   ← 外层区域结束
```

内层数组有两种来源，按数据形状选：

| 写法 | 数据形状 | 适用 |
| --- | --- | --- |
| `{{#each items}}` | 外层项自带 `items` 数组 | Provider / API 直接返回嵌套结构；SQL 用 `json_array(json_object(...))` 拼成 JSON 文本，渲染器会自动解析 |
| `{{#each order_items where order_no = order_no}}` | 两个**扁平**数组 | SQL 最常用：`orders` + `order_items` 两个 `single:false` 块，内层按字段相等过滤 |

`where` 的规则：

- 左边是**明细数组里的字段名**，右边是**当前作用域里的键**（`order_no`、`item.order_no` 都行）；
- 右边也可以写字面量，但要加引号：`where status = 'open'`；
- 比较时去首尾空格、忽略大小写，只支持单个等值条件；
- 右边取不到值会直接报错并说明写法，不会静默出空列表。

### 竖向合并单元格

同一个值在明细里连续出现时（同一物料的多个批次、同一订单的多行明细），可以让它在竖向合成一格。
在循环标记后面追加 `merge=` / `by=`：

```
{{#each items merge=3 by=material_id}}      ← 合并第 3 列，按 material_id 判断是不是同一条
{{#each items merge=A,C by=material_id}}    ← XLSX：同时合并 A、C 两列
{{#each items merge=3}}                     ← 不写 by：按渲染出来的文本比较
```

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| `merge=` | DOCX `1,2`（第几个单元格，1 起始）<br>XLSX `A,C` 或 `1,3`（列字母 / 1 起始列号） | 要竖向合并的列，逗号分隔、中间不能有空格 |
| `by=` | 字段名 | 合并分组键，**推荐写** |

**为什么不能只看「内容一样」**：两笔不同订单的日期可能是同一天，两个客户的名称可能都叫「张三」，
显示文本一样但根本不是同一条记录。所以合并的判据是**键**——写了 `by=` 就比字段值，
没写才退化成比渲染后的文本。

判定规则（全部满足才合并）：

1. 只在**声明它的那一次循环展开**里合并：跨表头、跨 `{{/each}}`、跨两个数据块永不合并；
2. 只合并**相邻**的行，中间隔了一行不同的就断组；
3. 分组键相同（`by` 的值，或渲染后的单元格文本）；
4. 键为**空**的格子永不合并——两个空格子不会变成一个大空格；
5. 一段至少 2 行才真的合并。

效果（`merge=1 by=material_id`，物料相同但批次不同）：

```
┌────────┬────────┐        ┌────────┬────────┐
│ 物料   │ 批次   │        │        │ B1     │
├────────┼────────┤   →    │ M1     ├────────┤
│ M1     │ B1     │        │        │ B2     │
│ M1     │ B2     │        ├────────┼────────┤
│ M2     │ B3     │        │ M2     │ B3     │
└────────┴────────┘        └────────┴────────┘
```

::: warning 注意
- **标记格会被清空**：单行循环里写 `{{#each items merge=1}}` 的那一格本身就是第 1 格，渲染完是空的，
  按文本比较永远合不上。要么把 `merge=` 指向别的列，要么用 `by=`。
- 同一列不要在外层和内层循环里都声明 `merge`，两层会各算一遍。
- `by=` 的字段取不到会直接报错（和循环变量取不到一样），不会静默不合并。
- XLSX 的竖向合并与模板里预先画好的合并区不要落在同一列，重叠时会跳过并打日志。
- 合并格的内容默认**靠上**；要垂直居中或靠下就在数据块配置里加 `mergeCellAlign`（见[合并单元格对齐](./data-blocks#合并单元格对齐)）。
:::

::: tip 区域循环与单行循环怎么选
- 一行就是一条记录 → **单行循环**（标记写在行里，不占额外标记行）。
- 一个外层项要带「多行」内容（主行 + 明细行、标题 + 若干条目）→ **区域循环**（标记各占一行）。
- `{{#each}}` 独占一行但**没有**配对的 `{{/each}}` 时，按单行循环处理。
:::

::: warning 限制
- 区域标记必须**独占一行 / 一段**，不能和别的文字写在同一个单元格里（那种情况按单行循环处理）。
- 段落块循环只处理段落，跨表格的块循环不支持。
- 循环块里**自带跨行合并**的单元格会被移除（复制出来的一份份没法还原成正确的合并区），需要竖向合并请用 `merge=`；
  只占一行的横向合并会随每份产出行重建，不受影响。
- 循环体里的嵌套表格按「单元格内的表」独立展开，不算跨表格循环。
:::

循环体里的字段也可以声明成图片字段（见[图片字段](./data-blocks#图片字段)），明细行里的图片会逐行渲染。

## DOCX 模板

支持的位置：**正文段落、表格（含嵌套表格）、页眉、页脚**。

```
报告编号：${report_no}          成品检验报告
检验员：${inspector:未填写}      日期：${date}
```

- 占位符可以和文字写在同一个段落里，不要求独占一行。
- Word 经常把一个占位符拆到多个 run（中途改过字体、从别处粘贴过），渲染器会先合并段落文本再替换，并把结果写回首个 run、沿用它的字体格式。**建议一个占位符保持同一字体**，格式最稳。
- 表格行循环：在要重复的那一行里任意单元格写 `{{#each items}}`，该行的边框、底色、字体随行复制。
- 段落块循环：`{{#each items}}` 和 `{{/each}}` 各自独占一段，中间可以有多段，整体按数组重复；段落块同样可以嵌套。
- 页眉页脚里的占位符、图片同样生效。
- 图片：占位符独占段落时（`${logo}` 单独一段）按图片字段的 `align` / `padding` 排版；和文字混排时（`签名：${sign} 完毕`）按行内图片插入，位置交给模板自身的排版。
- 不支持：条件判断、目录 / 域更新、公式。

## XLSX 模板

支持的位置：**任意工作表的单元格**。

| 单元格内容 | 生成结果 |
| --- | --- |
| `${qty}`（整格只有占位符） | 取到数字 → 写成数字单元格；取到布尔 → 写成布尔；其他 → 文本 |
| `数量：${qty} 件`（和文字混排） | 按文本替换，结果仍是字符串 |
| `{{#each items}}` | 该行按数组重复，标记本身会被清掉 |

- 只处理**文本单元格**：数字、布尔、公式单元格原样保留，不会被替换。
- 整格占位符取到数字时写成数字单元格，Excel 里能继续参与计算，导出 PDF 时也按数值排版；混排的则一律按文本。
- 行循环复制的是「单元格值 + 样式」，公式单元格会连公式一起复制；空数组时整行删除并上移。
- 图片必须**独占单元格**（`${logo}`）：图片锚定到该单元格，按 `align` 在格内水平对齐、四周留 `padding`；行高不够会自动撑高，列宽不够会自动加宽（只加不减）。
- 行循环复制单元格样式与行高；行内的横向合并会随每份产出行重建，跨行的合并区会被移除并提示改用 `merge=`（见[竖向合并单元格](#竖向合并单元格)）。
- 区域循环里的标记行会被整行删掉，所以 `{{#each}}` / `{{/each}}` 必须各自独占一行；行内标记则写在数据行里。
- 每个工作表都会渲染；完全空白的工作表在导出 PDF 时会被跳过，不会产生空白页。
- 不支持：公式重算（模板里的公式不重新计算）、条件判断。

## 两种模板对照

| 能力 | DOCX | XLSX |
| --- | --- | --- |
| 占位符位置 | 正文段落、表格单元格、页眉页脚 | 任意工作表的文本单元格 |
| 与文字混排 | 支持 | 支持（同一单元格内） |
| 明细行循环 | 表格行 / 表格区域 / 段落块 | 整行 / 行区域 |
| 循环闭合 | 行内标记隐式；区域与段落块需 `{{/each}}` | 行内标记隐式；区域需 `{{/each}}` |
| 递归渲染 | 支持（区域嵌套，层级不限） | 支持（区域嵌套，层级不限） |
| 图片 | 段落内，可与文字混排 | 必须独占单元格 |
| 合并单元格 | `merge=1,2`（1 起始单元格序号） | `merge=A,C` 或 `merge=1,3` |
| 数字 / 布尔 | 一律按文本渲染 | 整格占位符会写成数字 / 布尔单元格 |
| 页眉页脚 | 支持 | 无此概念 |

## 常见坑

1. **循环漏写 `each`**：`{{#user}}` 会被当成名为 `#user` 的占位符。渲染器直接拦截并提示正确写法。
2. **循环变量名对不上**：`{{#each report}}` 对应的是块编码 `report` 的数据块结果，不是数据库表名；块编码改了记得同步改模板。
3. **普通占位符取不到值不报错**：会输出空串。想暴露问题就给默认值，或用「模拟生成」看实际参数列表。
4. **Excel 标记写在非文本单元格**：数字格、公式格里写标记无效，先把单元格格式改成文本。
5. **图片字段的值不是图片**：空值按文本处理；URL 下载失败或格式不支持（svg / webp）会直接报错，错误信息里带字段名。
6. **不要指望条件判断**：目前没有 `{{#if}}`，需要按条件显示的内容，用数据块返回不同的数据，或拆成两份模板。
7. **嵌套循环的数组没取到**：内层 `{{#each items}}` 取的是「外层当前项的 items 字段」。外层是扁平 SQL 结果时它不存在，要么改用 `{{#each 明细块 where 外键 = 外键}}`，要么让数据源返回嵌套结构。
8. **区域标记写进了数据行**：`{{#each orders}}` 和 `${order_no}` 写在同一个单元格里时，会被当成单行循环，`{{/each}}` 也就白写了。标记要单独占一行。
